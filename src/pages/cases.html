1. Choose the regimes that apply

    aeroprove incident regimes eu nis2

    With none set, a new incident starts with no obligations and no clocks.

  2. Declare an incident

    aeroprove incident declare --title "Token used from an unknown country" --grade sev2 --finding ID

  3. Start the clocks

    A clock starts when somebody decides the organisation is aware, and that decision is recorded with its reason.

    aeroprove incident decide ID aware --because "..."
aeroprove incident duties

  4. Discharge or waive each duty

    aeroprove incident discharge ID "NIS2 early warning" --because "sent to the CSIRT"
aeroprove incident waive ID "GDPR Article 34" --because "no personal data involved"

  5. Work a playbook

    aeroprove incident playbooks
aeroprove incident propose ID account-compromise
aeroprove incident step ID account-compromise STEP done --because "..."

    The shipped playbooks cover account compromise, phishing, malware on an endpoint, a lost device and exposed data.

  6. Act on another platform, with a second person

    aeroprove action add okta-suspend-user --org example
aeroprove incident act ID okta-suspend-user okta:USER --because "..."
aeroprove incident act-approve ID 1

    The exact request is shown before anybody approves it, and it is sent only when a second person does.

The deadlines are the published ones, counted from the decision, not legal advice. Notices to the people affected are drafted, planned and sent with aeroprove notify.
